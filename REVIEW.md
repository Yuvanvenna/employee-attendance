# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health()` / line 72 | Does not check if MongoDB is alive; always returns 200 OK. | If MongoDB is stopped, `/health` still returns 200 instead of 503 Service Unavailable. | Added `client.admin.command("ping")` inside a try/except block; raises HTTPException(503) if ping fails. |
| 2 | `create_employee()` / line 79 | Race condition via check-then-insert (`find_one` then `insert_one`). | Two concurrent `POST /employees` requests with identical `emp_code` can both pass the check and create duplicate records. | Created a unique index on `emp_code` in MongoDB and caught `DuplicateKeyError` to return 409 Conflict. |
| 3 | `create_employee()` / line 82 | Naive local datetime via `datetime.now()`. | Saved `created_at` in MongoDB lacks UTC awareness, causing timezone drift across environments. | Replaced with `datetime.now(timezone.utc).replace(microsecond=0)`. |
| 4 | `create_employee()` / line 84 | Returns `created_at` as a Python datetime object instead of epoch milliseconds integer. | Fails OpenAPI schema validation (`EpochMillis`). | Converted `created_at` to integer epoch milliseconds before returning response. |
| 5 | `create_employee()` / line 78 | Does not validate that `shift_start` differs from `shift_end`. | `POST /employees` with `shift_start == shift_end` succeeds (201) instead of returning 422 Unprocessable Entity. | Added Pydantic field validator ensuring `shift_start != shift_end`. |
| 6 | `list_employees()` / line 93 | Incorrect pagination skip formula: `skip = page * page_size`. | Requesting `page=1` skips the first 20 records (returns items 21–40 instead of 1–20). | Changed formula to `skip = (page - 1) * page_size`. |
| 7 | `list_employees()` / line 94 | Total count ignores filter: `total = db.employees.count_documents({})`. | Requesting `GET /employees?department=Engineering` returns filtered items but `total` reflects the entire company. | Changed to `total = db.employees.count_documents(q)`. |
| 8 | `list_employees()` / line 95 | Missing mandatory sort by `emp_code` ascending. | Employees are returned in arbitrary MongoDB natural insertion order. | Added `.sort("emp_code", ASCENDING)` to the query cursor. |
| 9 | `punch_in()` / line 101, 113 | Unhandled `None` employee lookup crashes with 500 when accessing `emp["shift_start"]`. | `POST /attendance/punch-in` with nonexistent `emp_code` throws unhandled TypeError (500) instead of 404. | Added explicit check: if employee is not found, raise HTTPException(404, "Employee not found"). |
| 10 | `punch_in()` / line 102 | `datetime.fromtimestamp(ms / 1000)` produces naive local time; does not truncate milliseconds. | Attendance calculations deviate across servers; violates R1 requirement to truncate instants to whole seconds. | Truncated milliseconds to seconds (`ms // 1000`) and constructed UTC-aware datetime. |
| 11 | `punch_in()` / line 103 | Uses local calendar date (`ts.date()`) instead of IST calendar date; ignores overnight shifts (R1). | Punch-in at 01:00 UTC assigns the wrong date; overnight shift punch-in before `shift_end` is assigned to current day instead of previous day. | Built `get_attendance_date()` evaluating IST time and shifting overnight punch-ins before `shift_end` to previous day. |
| 12 | `punch_in()` / line 104 | Concurrency check-then-insert race condition on `(emp_code, date)`. | Two concurrent punch-in requests for the same employee on the same date can both succeed. | Created unique compound index on `("emp_code", 1), ("date", 1)` and caught `DuplicateKeyError` to return 409. |
| 13 | `compute_overtime()` / line 44 | Fails on overnight shifts (shift end on next day) and ignores 30-minute threshold (R3). | Overtime < 30 min is counted; overnight shifts calculate negative or massive overtime. | Added overnight calendar day shift and enforced `overtime_minutes = diff // 60 if diff >= 1800 else 0`. |
| 14 | `compute_work_hours()` / line 41 | Uses Python `round()`, which applies banker's rounding (round to nearest even) instead of half-up (R4). | Values such as 4.125 round down to 4.12 instead of 4.13. | Replaced with `decimal.Decimal` and `ROUND_HALF_UP`. |
| 15 | `list_attendance()` / line 144–150 | Loads entire collection into Python memory for sorting (`docs.sort()`), returns non-schema `id` field, and ignores `date_from > date_to`. | Server runs out of memory on ~100k records; schema validation fails due to `"id"`; invalid date range returns 200 instead of 422. | Validated `date_from <= date_to` (422), delegated sorting and pagination to MongoDB cursor (`.sort([("date", -1), ("emp_code", 1)]).skip().limit()`), and removed internal `_id` without adding `"id"`. |

### Not a defect
- **PyMongo returning naive UTC datetimes:** By default, PyMongo returns BSON dates as naive datetimes in UTC. This is standard driver behavior and was intentionally documented in `DATA_MODEL.md`. Rather than being a defect, it is handled deterministically at the API boundary using `dt_to_ms` which assigns UTC tzinfo before converting to epoch milliseconds.
